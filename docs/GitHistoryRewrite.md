# Git History Rewrite

> **Scope:** On 2026-07-15 the repository history was rewritten with `git filter-repo` to remove ~3.5 GB of CCC test data, a committed Next.js build cache, and stale image assets from every commit. `.git` went from **1.3 GB to 14 MB**. This document records what was removed, what was kept, the evidence that nothing was lost, and what collaborators must do.

## Why

`past_contests/` test data was deleted from the working tree in #162 and moved to R2 (see [R2Migration.md](./R2Migration.md)). But deleting files in a commit does not remove their blobs from history — every prior commit still referenced them, so `.git` stayed at **1.3 GB** and every fresh clone paid that cost.

The raw test data totalled ~3.5 GB (`.in` 2,853 MB + `.out` 685 MB). Git's zlib + delta compression packed that to ~1.3 GB — the 3.5 GB → 1.3 GB gap is compression, not missing data.

Removing blobs from history requires rewriting every commit, which changes all SHAs and requires a force-push. That was done once, deliberately, with the branch protection `allow_force_pushes` toggled on for the push and back off immediately after.

## What Was Removed

7,334 distinct paths, all verified absent from the then-current `main`:

| Category           | Count | Notes                                                                                                                           |
| ------------------ | ----- | ------------------------------------------------------------------------------------------------------------------------------- |
| `.in` test data    | 4,092 | 2,853 MB raw                                                                                                                    |
| `.out` test data   | 2,653 | 685 MB raw                                                                                                                      |
| `website/.next/**` | 203   | Committed Next.js build cache (221 MB of `.pack`, plus 129 internal `.js`/`.json`). Regenerated by every build; now gitignored. |
| `*/src/assets/**`  | 11    | Stale images from the pre-restructure layout                                                                                    |
| Empty directories  | 375   | Directories whose only contents were the above; git cannot store an empty directory                                             |

The test data lived at **five** historical locations because the project was restructured several times (`frontend-react/mmhs-website/` → `mmhs-website/` → `website/`):

```
frontend-react/mmhs-website/public/past_contests/<year>/<problem>/test_data/
mmhs-website/public/past_contests/<year>/<problem>/test_data/
website/public/past_contests/<year>/<problem>/test_data/
frontend-react/mmhs-website/public/raw_test_data/
"2016+ test cases/"                                  # note the space in the directory name
```

Filtering by a single path misses most of these, which is why the final filter matched by **file extension** instead.

## What Was Kept

- **All 332 `solution*.txt` files** and their full history. Solutions lived _inside_ `past_contests/<year>/<problem>/` alongside `test_data/`, so a directory-based filter would have destroyed them (see [Gotchas](#gotchas)).
- **All source code**, unchanged. Zero code/text files were removed outside `website/.next`.
- **All live images** under `website/public/images/`.
- **All contributor history** — commits from Morgan-Su (×10), tinyfold88 (×4), John Liao, AStrangePotato, and every solution PR.

## The Command

Run against a fresh `--mirror` clone:

```bash
git filter-repo --force --invert-paths \
  --path-glob '*.in' \
  --path-glob '*.out' \
  --path website/.next \
  --path website/src/assets \
  --path mmhs-website/src/assets \
  --path frontend-react/mmhs-website/src/assets
```

Matching `.in`/`.out` by extension catches the test data at every historical prefix automatically, while `solution*.txt` is untouched. Then:

```bash
git push --force origin main supabase-refactor
```

## Verification

Every check below was run before the force-push.

| Check                                   | Result                                                     |
| --------------------------------------- | ---------------------------------------------------------- |
| `main` HEAD tree vs GitHub              | **Identical** — `23de2e04570550821c105fc561e60332bf3054c1` |
| `supabase-refactor` HEAD tree vs GitHub | **Identical** — `75e3036ae2a94a5709c8a8474085d75017a38d71` |
| Files at HEAD                           | 124 → 124                                                  |
| Solution files removed                  | **0** (all 332 intact)                                     |
| Code/text files removed outside `.next` | **0**                                                      |
| Live `public/images` removed            | **0**                                                      |
| `.in`/`.out` remaining in history       | **0**                                                      |
| `git fsck --full`                       | Clean                                                      |
| `.git` size                             | 1.3 GB → **14 MB**                                         |

An identical HEAD tree hash is the strongest available guarantee: it proves every file in the current checkout is byte-for-byte unchanged.

Post-push, a fresh `git clone` from GitHub confirmed: `.git` = 14 MB, 332 solutions present, 0 test-data objects, 124 files at HEAD.

## R2 Parity Proof

Since test data now exists only in R2, parity was verified against the true pre-deletion tree (`8f30c584`, the parent of the #162 deletion commit) rather than a whole-history object listing.

Test-case counts per problem, git vs `GET /contests/:year/:code/list`:

| Metric                                   | Value     |
| ---------------------------------------- | --------- |
| Problems with test data in git           | 255       |
| Test cases in git (`.in` files)          | 4,546     |
| Test cases in R2                         | **4,829** |
| Problems missing from R2                 | **0**     |
| Problems where R2 has **fewer** than git | **0**     |

R2 is a strict **superset**: +1 case on 188 problems, +2 on 38, +3 on 5, +4 on 1 — consistent with sample cases added by the "converted test cases with sequential numbering" normalization.

**Caveat:** test cases were renumbered when moved to R2, so filenames cannot be compared 1:1. Only counts were compared; identical counts do not strictly prove identical bytes.

## Commits Pruned

370 → **365**. `filter-repo` drops commits that become empty. The 5 dropped touched nothing but removed data:

```
feat: add 2016-2025 converted test cases with sequential numbering
fixed some test cases again          (×2)
fix home page image loading          (only touched dead src/assets images)
new changes
```

No commit containing code or solutions was lost.

## Backups

Retained on the maintainer's machine, not in the repo:

- **`ccc-prerewrite-backup.bundle`** (1.3 GB) — complete pre-rewrite history, `git bundle verify` clean. Kept indefinitely.
- **`ccc-archive/`** (9.1 MB) — every removed non-test-case file (the 11 stale images).
- **`ccc-stashes/`** (420 KB) — contents of local stashes. `git bundle --all` does **not** include `refs/stash`, so stashes needed separate extraction.

## Instructions for Collaborators

Every commit SHA changed. **Do not `git pull`, `git merge`, or `git rebase`** against the new history — your local commits carry the old history, so git will try to replay them onto the new base and reintroduce the deleted test data.

```bash
# 1. Save anything not pushed — stashes and local commits live only on your machine
git stash list
git log origin/<branch>..<branch>
git format-patch origin/<branch> --stdout > ~/my-work.patch   # if you have unpushed commits

# 2. Re-clone
cd ..
mv CCCSolutions CCCSolutions-old        # rename, don't delete, until you've confirmed
git clone https://github.com/CCCSolutions/CCCSolutions.git
cd CCCSolutions/website && bun install

# 3. Re-apply your patch if needed, then remove CCCSolutions-old
```

The code itself is unchanged — only history was rewritten.

## Gotchas

- **Filter by extension, not directory, when valuable files are interleaved with junk.** `solution*.txt` lived inside `past_contests/` next to `test_data/`. An initial pass that removed `past_contests` wholesale silently pruned **45 commits** of contributor history to save **0 MB** (solution files total well under 1 MB). Filtering `.in`/`.out` by extension kept them and reduced pruned commits to 5.
- **Audit every historical path first.** Data lived at five locations across three refactors, plus dirs named `raw_test_data` and `2016+ test cases` (with a space). A single `--path` catches almost none of it.
- **Don't trust a shallow parity check.** A first attempt enumerated problems from `git rev-list --all` (which mixes every historical state, not the final tree) and only asked "does `/list` return _any_ tests?" — never comparing counts. Both its numbers were wrong.
- **`allow_force_pushes` must be toggled on** in Settings → Branches to push a rewrite, and turned back off after.
- **GitHub retains old blobs via `refs/pull/*` indefinitely** (server-side). `git clone` never fetches those, so clones are slim regardless.
- **Cloudflare rate limiting does not count cache hits.** Unrelated to the rewrite, but discovered while testing: repeated requests to a cached endpoint (`cf-cache-status: HIT`) never increment the rate-limit counter.
